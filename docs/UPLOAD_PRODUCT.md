# Upload to a better book

## Core promise

Upload a PDF, DOCX, or legacy DOC. Get a downloadable, standards-based EPUB that reads comfortably on Android, with a preview and a clear account of what was preserved, changed, or left uncertain. Conversion is private by default; publishing a book to the world is a separate explicit action.

## The first usable journey

1. Sign in; choose a file. Show supported types, proposed pilot limits, retention, and how to delete the upload before transfer.
2. Set the title/author/language and choose **Comfortable reading**, **Preserve the original**, or **Smaller download**. Detect file type and suggest a route; let the user correct the language. Never infer that English OCR is suitable for Telugu.
3. Show real stages: uploading, inspecting, extracting/OCR, assembling, validating, ready or needs review. A page count is useful; a fabricated time estimate is not.
4. Preview representative pages and chapters. Offer a source/text comparison for PDF. Summarize missing images, uncertain OCR, reading-order warnings, and navigation coverage separately from mechanical validity.
5. Download a conventional `.epub`, plus an optional quality report and searchable PDF. On Android, save it in Downloads and use the OS Open With/Share flow to select an EPUB reader. A reader app is needed; Android itself is not an EPUB renderer.
6. Provide retry, language correction, and Delete files. Keep processing and download links scoped to the signed-in owner. Downloads expire; users keep their downloaded files.

## What enhanced means

| Enhancement | Default behavior | Review boundary |
|---|---|---|
| Typography | Reflowable text, sensible line height/margins, scalable images; reader controls size/theme | Test Telugu shaping, conjuncts and word breaking on Android. Embed fonts only with a suitable license. |
| Navigation | Preserve headings; build chapter TOC, landmarks and source page references where known | Never label guessed headings or PDF page indices as verified print structure. |
| Cleanup | Normalize Unicode; detect recurring headers/footers and broken line wraps | Keep a reversible change log; avoid aggressive dehyphenation or spelling changes in unfamiliar scripts. |
| Illustrations | Preserve figures/captions near the correct text; link to original scans | Human descriptions for meaningful art; no autogenerated accessibility claim. |
| Metadata | Let the user confirm title, author, language and cover | Do not invent publication dates or rights metadata. |
| Rich books | Preserve footnotes, links, tables and equations when representable | Warn on losses and offer original-page view rather than silently flattening everything. |
| Reading aids | Later: reviewed glossary, transliteration, parallel translation, narration | Optional, labeled derivatives. Original prose and artwork remain intact. |

An enhanced EPUB remains a normal EPUB. Start with progressive enhancement that works without JavaScript, remote assets, or an internet connection. Interactive widgets are a later, reader-specific feature, not a requirement to open the book.

## Proposed pilot scope

- PDF, DOCX, DOC; one file per job, initially up to 50 MiB and 300 PDF pages. These are proposed product limits, to be adjusted after memory/runtime benchmarks.
- Standard reflowable EPUB as the default; original-file download and optional searchable PDF. Fixed-layout EPUB/CBZ for highly illustrated material only after separate testing.
- English and Telugu as tested launch languages; other languages marked experimental until evaluated.
- Private accounts, basic quotas, per-job worker isolation, short-lived signed transfers, cancellation and deletion.
- No arbitrary URL imports, macro execution, custom scripts, DRM removal, automatic public publication, or mandatory external AI processing in the initial product.

## Android acceptance checks

Test an inexpensive physical Android phone with Chrome and Readest, then a second EPUB reader and an offline flow. Check installation/open-with behavior, download MIME type `application/epub+zip`, chapter navigation, inline images, long tables, footnotes, large font sizes, dark mode, Telugu shaping, TalkBack and reading progress. Also check a desktop reader so we do not optimize for one renderer. Record exact app/OS versions; no universal compatibility claim before these tests.

## Features worth building after the core works

- A review queue that lets a family or community fix difficult words while seeing the scan.
- Story-level exports from a magazine issue and serial reading paths across decades.
- A low-bandwidth preset and optional image-quality control that previews the file-size tradeoff.
- Human narration and synchronized EPUB audio, with offline audio size made visible.
- Optional opt-in cross-device progress and a rights-cleared public shelf.

Avoid launching recommendations, chat, gamification, and translation ahead of faithful conversion. The first success is an entire book that reads in the right order and retains its illustrations.
